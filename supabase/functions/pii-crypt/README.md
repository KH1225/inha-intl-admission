# 이메일·연락처 암호화 (pii-crypt)

지원자 **이메일·연락처·추가 이메일**과 **메일 발송 기록의 받는 주소**를 AES-256 으로 암호화해 DB에 저장합니다.

- DB에는 `enc:v1:…` 암호문만 남습니다.
- 암호화 열쇠는 **DB가 아니라** Supabase Edge Functions 의 Secret `PII_KEY` 에만 있습니다.
  DB가 통째로 유출되거나 SQL 로 뚫려도 이 값들은 읽을 수 없습니다.
- 화면에서는 지금과 똑같이 보입니다. 로그인한 사람의 권한(RLS)으로 볼 수 있는 지원자만 서버 함수가 풀어 줍니다.
- 출신고교·성적·이름·국적 등은 집계·검색에 쓰여 암호화하지 않습니다 (역할별 열람 제한으로 보호).

## 순서 (꼭 이 순서대로)

### 1. 사전 점검
Supabase → SQL Editor 에서 `sql/2026-11-16_연락처_암호화_사전점검.sql` 실행 → 결과 확인
- 2번(규칙·색인) 또는 3번(함수·뷰)에 무언가 나오면 **멈추고** 결과를 보내 주세요. 함께 고쳐야 합니다.

### 2. 암호화 열쇠 만들기
1. 아무 웹페이지에서 **F12** → **Console(콘솔)** 탭
2. 아래 한 줄을 붙여 넣고 Enter
   ```js
   btoa(String.fromCharCode(...crypto.getRandomValues(new Uint8Array(32))))
   ```
3. 나온 44자리 값(따옴표 제외)이 열쇠입니다.
4. **사본을 안전한 곳에 보관하세요.** 예: 부서 비밀번호 관리 도구, 출력해 잠금 보관함
   - 열쇠를 잃어버리면 암호화된 이메일·연락처는 **영영 되살릴 수 없습니다.**
   - GitHub·메일·메신저·채팅에는 절대 붙여 넣지 마세요.

### 3. Secret 등록
Supabase → Edge Functions → **Secrets** → 이름 `PII_KEY`, 값 = 2단계의 열쇠 → 저장

### 4. 서버 함수 배포
Supabase → **Edge Functions** → **Deploy a new function** → **Via Editor**
- 함수 이름: `pii-crypt` (정확히 이 이름)
- 이 폴더의 `index.ts` 를 통째로 붙여 넣고 **Deploy**
- **Verify JWT 는 켠 그대로** 둡니다 (로그인한 사람만 부를 수 있어야 함)

### 5. 메일 발송 함수 다시 배포
Edge Functions → `send-interview-mail` → 편집기에 새 `supabase/functions/send-interview-mail/index.ts` 를 통째로 붙여 넣고 **Deploy**
(암호화된 이메일을 풀어서 보내고, 발송 기록도 암호문으로 남깁니다)

### 6. 현황판 파일 올리기
GitHub 저장소에 바뀐 파일을 올립니다: `index.html`, `js/` 폴더, `assets/js/` 폴더, `demo/app/`, `supabase/`, `sql/`
1~2분 뒤 현황판을 **Ctrl+Shift+R** (강력 새로고침)

### 7. 기존 자료 암호화
총괄관리자로 로그인 → 상단 **연락처 암호화** → **지금 암호화**
→ "✓ 모두 암호화되어 있습니다" 가 나오면 완료
(다른 직원 PC 에 열려 있는 현황판도 모두 새로고침하게 해 주세요)

### 8. 평문 저장 막기
SQL Editor 에서 `sql/2026-11-16_연락처_암호화_잠금.sql` 실행 → 두 줄이 나오면 완료

### 9. 확인
- 1단계 사전점검 SQL 을 다시 실행 → 4번의 **평문 개수가 모두 0**
- Table Editor 에서 applicants 표를 열면 email·phone 칸이 `enc:v1:…` 로 보임
- 현황판 지원자 상세에서는 이메일·연락처가 정상적으로 보임
- 안내 메일 → **내 메일로 테스트 발송** 이 오는지

## 문제가 생기면
- "PII_KEY 가 없거나 형식이 틀렸습니다" → 3단계 Secret 이름·값 확인 (44자리, 앞뒤 공백 없이)
- "암호화 서버 함수(pii-crypt)가 아직 Supabase에 없습니다" → 4단계 함수 이름 확인
- 이메일·연락처가 비어 보임 → 열쇠가 바뀌었을 수 있습니다. 처음 등록한 열쇠로 Secret 을 되돌리세요.

## 남는 위험 (알고 계셔야 할 것)
- Supabase **계정**(대시보드 로그인)을 빼앗기면 Secret 도 바꿀 수 있으니, 계정에 **2단계 인증**을 꼭 켜 두세요.
- 총괄관리자·국제교류팀 **직원 계정**이 털리면 그 사람 권한만큼은 화면에서 볼 수 있습니다 (암호화로 막을 수 없는 부분 — 로그인 잠금·자동 로그아웃·열람 기록으로 대응).
